# Expense Tracker — Design Overview (v1)

Date: 2026-08-04. Status: approved.

A personal expense tracker built as a portfolio project whose explicit goal
is to demonstrate **production-quality engineering**, not feature count.
Reviewers experience it as a live demo (one-click, per-visitor sandbox)
backed by a repo that reads like a production codebase.

This document is the entry point. The detail lives in:

- [`schema.md`](./schema.md) — data model: 6 tables, constraints, indexes,
  budget and recurring semantics.
- [`api.md`](./api.md) — API surface, sessions, CSRF, rate limits, CSP,
  error envelope, ephemeral demo accounts.
- [`delivery.md`](./delivery.md) — frontend, testing per layer, CI
  pipeline, deploy, nightly cron, docs.

## Fixed decisions (user-mandated, not revisitable)

- Stack: React + Vite + TypeScript, Fastify, PostgreSQL, Drizzle.
- Money as integer minor units (`bigint`), never float.
- Session-cookie auth (httpOnly), not JWT in localStorage.
- Design: Linear-style — dark-first, near-monochrome, one accent, 8px
  grid, dense data tables, tabular numerals.
- Single currency (LKR); `currency` column present throughout with
  `CHECK (currency = 'LKR')`.

## Scope (v1)

- **Expenses** — CRUD, expenses-only (no income). Fields: amount,
  category, date (date-only), description, optional notes. Filterable,
  searchable, keyset-paginated list.
- **Categories** — user-defined, flat, seeded defaults at signup,
  archive-not-delete.
- **Budgets** — per category per calendar month, effective-from model
  (set once, applies forward), no rollover, no overall cap.
- **Recurring expenses** — weekly/monthly fixed frequencies, month-end
  clamp computed from the anchor day (never from the previously clamped
  date), edits apply forward only, no backfill of past start dates,
  generated by an idempotent catch-up job on the nightly cron.
- **Reports** — fixed dashboard with date-range drill-down: summary,
  spend-vs-budget, monthly trend, category breakdown, top expenses. All
  aggregation in SQL. These endpoints are the seam for future AI insights.
- **CSV export** — small utility, honors list filters. (Import is v2.)
- **Auth** — open signup (email+password) + per-visitor ephemeral demo
  accounts. No email verification, no password reset (documented cut).

## Production-quality bar (all in scope)

- Tests: unit (domain logic), API integration against real Postgres
  (including ownership-isolation tests), Playwright E2E — exactly 3
  flows: signup, add expense, see it on dashboard.
- CI: lint, typecheck, test, build, E2E on every PR and push to main;
  deploy job gated to push-to-main with `needs:` on all stages.
- Security: argon2id, hashed session tokens, sliding expiry with 90-day
  absolute cap, SameSite=Lax + Origin-check CSRF, rate limits, strict
  self-only CSP, zod validation everywhere via shared schemas.
- Observability: pino structured logs, request IDs, `/health`, optional
  Sentry.
- Docs: README with live-demo link, `docs/architecture.md`, four ADRs —
  sessions-over-JWT, integer-minor-units money, aggregation-in-SQL,
  ephemeral demo users.

## Architecture (one paragraph)

pnpm monorepo — `apps/api` (Fastify + Drizzle), `apps/web` (React/Vite),
`packages/shared` (zod schemas = the single API contract). Production is
one Docker container on Render (free) serving `/api` and the built SPA
same-origin, against Neon Postgres (free). Local dev mirrors prod via the
Vite proxy. A nightly GitHub Actions cron runs directly against the
database: reap demo users → sweep expired sessions → generate recurring
occurrences; steps independent, any failure exits non-zero.

## Non-goals (v1) — and what unblocks them

| Deferred | Unblocked by |
|---|---|
| CSV import | dedup key queryable on existing columns |
| AI spending insights (stretch, post-v1) | consumes the existing report endpoints |
| Budget alerts / notifications | none needed — explicit non-goal, no channel exists |
| Multi-currency | widen `currency` CHECKs; amounts already minor-units |
| Income tracking | additive `type` column |
| Password reset / email verification | adding a transactional-email provider |
| Category hierarchy, tags, receipts, payment methods | out of scope, additive if ever wanted |

## Decision history (deviations during design)

- Recurring expenses were initially declared v2, then **pulled into v1**
  with tight constraints (weekly/monthly only, clamp, forward-only edits,
  cron generation). Acknowledged ~+20% scope.
- "Budget alerts" were clarified to be a misnomer for the nightly cron —
  no alert feature exists or is planned for v1.
- Shared writable demo account was rejected as a public write surface;
  replaced by per-visitor ephemeral demo users (cap 100, reaped after
  24h).
